# แผนสำรองและกู้คืนข้อมูล (ฉบับย่อ — ยังไม่สมบูรณ์) — 19 พ.ย. 2026

## ข้อมูลอยู่ที่ไหน และต้องสำรองอะไร

| ข้อมูล | อยู่ที่ | วิธีสำรอง | สถานะ |
|---|---|---|---|
| ฐานข้อมูลเว็บ (สิทธิ์, งาน, รูป, ลิงก์, รหัสสั้น) | Firestore | (ก) สำรองอัตโนมัติของ Google (ข) ไฟล์สำรองที่เราถือเอง `scripts/backup-firestore.mjs` | (ข) **ทดสอบกู้คืนแล้วบนฐานข้อมูลจำลอง** (ก) ยังไม่ได้ตั้งค่า ต้องเปิดบัญชีชำระเงิน |
| บัญชีผู้ใช้เว็บ | Firebase Authentication | `firebase auth:export` | ยังไม่ได้ทำ ข้อควรระวัง: export ได้รหัสผ่านเฉพาะแบบ scrypt และต้องเก็บค่า hash ของโปรเจกต์ไว้ด้วย |
| ไฟล์รูป | Cloudflare R2 | ต้องคัดลอกไปผู้ให้บริการที่สอง (Super Slurper หรือ rclone) หน้าคู่มือ R2 ที่อ่านไม่ได้ระบุการทำสำเนาข้ามบัคเก็ตหรือเวอร์ชันของไฟล์ในตัว | ยังไม่ได้ทำ |
| กุญแจเซ็นสิทธิ์ (`STUDIO_SIGNING_PRIVATE_KEY`) และ `STUDIO_SHARE_SECRET` | ไฟล์ env บนเซิร์ฟเวอร์ | เก็บสำเนาในที่ปลอดภัย (ตัวจัดการรหัสผ่าน) ห้ามเก็บใน git ถ้ากุญแจเซ็นสิทธิ์หาย จะออกสิทธิ์ใหม่ให้แอปที่เชื่อกุญแจเดิมไม่ได้ | เจ้าของต้องทำเอง |
| เครื่องบูธ: รูปต้นฉบับ + ข้อมูลแอป | โฟลเดอร์รูปที่เลือก + โฟลเดอร์ข้อมูลของแอป | คัดลอกทั้งโฟลเดอร์รูปและไฟล์ `*.json` ของแอปไปไดรฟ์ภายนอกทุกคืน (ยกเว้นไฟล์ `license-*.json` และ PIN ซึ่งผูกกับเครื่อง) | ยังไม่มีสคริปต์ |
| **เทมเพลตของแอป Desktop** | **localStorage ของหน้าต่างแอป (ไม่ใช่ไฟล์ในโฟลเดอร์ข้อมูล)** | ใช้ปุ่มส่งออกไฟล์เทมเพลตของแอปเป็นระยะ | **ความเสี่ยง:** การคัดลอกไฟล์ข้างบนไม่ครอบคลุมเทมเพลต |

## ข้อเท็จจริงจากคู่มือ Google (อ่านเมื่อ 2026-11-19)

- Firestore สำรองอัตโนมัติ: ตั้งได้ 1 ตารางรายวัน + 1 รายสัปดาห์ เก็บสูงสุด 14 สัปดาห์ **การกู้คืนเขียนลงฐานข้อมูลใหม่เสมอ ไม่ทับของเดิม** ต้องเปิดบัญชีชำระเงิน ไม่รวมกฎความปลอดภัยและนโยบาย TTL ([คู่มือ](https://docs.cloud.google.com/firestore/native/docs/backups))
- PITR ย้อนได้ 7 วัน ปิดไว้ตามค่าเริ่มต้น มีค่าเก็บข้อมูลและไม่มีส่วนฟรี ([คู่มือ](https://docs.cloud.google.com/firestore/native/docs/pitr))
- Export/Import: นำเข้าแล้วเอกสารที่ ID ซ้ำจะถูกเขียนทับ เอกสารที่ไม่อยู่ในไฟล์จะคงเดิม ([คู่มือ](https://docs.cloud.google.com/firestore/native/docs/manage-data/export-import))

## ผลซ้อมกู้คืน (ฐานข้อมูลจำลองบนเครื่องพัฒนา)

`node scripts/restore-drill.mjs` ผ่านครบ 11 ขั้น: สร้างข้อมูลจริงด้วยโปรโตคอลบูธ → สำรอง (56 เอกสาร, 4.5 วินาที) → **ลบทั้งฐานข้อมูล** → ลิงก์แขกและสิทธิ์บูธพังจริง (503) → กู้คืน (4.2 วินาที ตรวจลายเซ็นไฟล์และจำนวนเอกสารครบ) → ลิงก์แขกกลับมาเปิดได้ สิทธิ์บูธต่ออายุได้โดยไม่ต้องสมัครใหม่ และบูธอัปโหลดรอบใหม่ได้
ขนาดใหญ่ขึ้น (เอกสารสังเคราะห์ 20,000 รายการ): สำรอง 11 วินาที กู้คืน 43 วินาที ชนิดข้อมูลพิเศษกลับมาครบ
ข้อจำกัด: ตัวเลขเวลาจากฐานข้อมูลจำลองในเครื่อง ไม่ใช่ Firestore จริง การกู้คืนบน Firestore จริงใช้การสำรองของ Google (ลงฐานข้อมูลใหม่แล้วชี้เว็บไปที่ใหม่) สคริปต์กู้คืนของเราตั้งใจให้ทำงานกับ emulator เท่านั้น

## ยังไม่ได้ทำ

เปิดสำรองอัตโนมัติและ PITR บนโปรเจกต์จริง, สำรอง Auth, คัดลอก R2 ไปผู้ให้บริการที่สอง, สคริปต์สำรองเครื่องบูธ, กำหนดเป้าหมาย RPO/RTO กับเจ้าของ, ซ้อมกู้คืนบน staging จริง
