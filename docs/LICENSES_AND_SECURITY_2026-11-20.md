# สัญญาอนุญาตและช่องโหว่ (2026-11-20)

สรุป: ไลบรารีที่ใช้งานจริงของทั้งเว็บและโปรแกรมตู้ใช้เชิงพาณิชย์ได้ทั้งหมด มีข้อผูกพันที่ต้องทำ 3 ข้อ (ด้านล่าง)
และหลังแก้แล้วไม่มีช่องโหว่ที่ทราบในไลบรารีที่ใช้งานจริง (`npm audit --omit=dev` = 0 ทั้งสองโปรเจกต์)

SBOM (CycloneDX, เฉพาะไลบรารีที่ใช้งานจริง) สร้างด้วย `npm sbom --sbom-format cyclonedx --omit dev`:
- เว็บ: `docs/sbom/sbom.cdx.json` (250 รายการ)
- โปรแกรมตู้ (repo PhotoboothKoKo): `docs/sbom/sbom.cdx.json` (36 รายการ)

## สัญญาอนุญาต

| โปรเจกต์ | แพ็กเกจที่นับ (จาก package-lock รวมแพ็กเกจเฉพาะระบบ) | สัญญาอนุญาต |
|---|---|---|
| เว็บ | 313 | MIT 142, Apache-2.0 124, BSD-3-Clause 12, ISC 12, LGPL-3.0-or-later 14 (libvips ผ่าน sharp), อื่น ๆ แบบเปิด 9 |
| โปรแกรมตู้ | 44 | MIT 34, ISC 7, OFL-1.1 2 (ฟอนต์), Apache-2.0 1 |

ไม่พบ GPL, AGPL, SSPL, BUSL หรือแบบห้ามใช้เชิงพาณิชย์

แพ็กเกจที่ package-lock ไม่ระบุสัญญาอนุญาต: `limiter@1.1.5` (ใช้ผ่าน `jwks-rsa`) ตรวจไฟล์ LICENSE แล้วเป็น MIT

### ข้อผูกพันที่ต้องทำ
1. **libvips (LGPL-3.0)** มากับ `sharp` ที่ใช้ย่อรูปบนเซิร์ฟเวอร์ ใช้แบบไลบรารีแยก (dynamic) ไม่ได้แก้โค้ด จึงใช้เชิงพาณิชย์ได้ ต้องเก็บประกาศสัญญาอนุญาตไว้ และถ้าแจกจ่าย Docker image ให้คนอื่น ต้องให้ผู้รับเปลี่ยนเวอร์ชัน libvips เองได้ (ตอนนี้ใช้บนเซิร์ฟเวอร์ของเราเอง ไม่ได้แจกจ่าย)
2. **ฟอนต์ OFL-1.1** ในโปรแกรมตู้ และฟอนต์ Google (Cormorant Garamond, IBM Plex Sans Thai, Noto Serif Thai) บนเว็บ: ใช้และฝังได้ ห้ามขายตัวฟอนต์แยก ต้องแนบประกาศสัญญาอนุญาต
3. **Electron / Chromium** ในตัวติดตั้งโปรแกรมตู้: Electron (MIT) แนบไฟล์ `LICENSES.chromium.html` มาให้แล้ว ต้องคงไว้ในตัวติดตั้ง

ซอฟต์แวร์ของผู้ผลิตกล้องที่ **ไม่ได้** อยู่ในตัวติดตั้ง: EOS Webcam Utility, digiCamControl (ลูกค้าติดตั้งเองถ้าต้องการ) ถ้าในอนาคตใส่ Canon EDSDK ต้องทำตามสัญญาของ Canon (แจกได้เฉพาะไฟล์ DLL ที่อนุญาต และต้องต่ออายุทุกปี)

## ช่องโหว่

| โปรเจกต์ | ก่อนแก้ | หลังแก้ |
|---|---|---|
| เว็บ | high 4 รายการ จากต้นเหตุเดียว: `@grpc/grpc-js@1.9.16` ที่ `@firebase/firestore` (Firebase ฝั่งหน้าเว็บ) ล็อกเวอร์ชันไว้ (GHSA-m9gg-hp2v-232j, GHSA-f596-whhp-79r4 ทั้งคู่แก้ใน 1.13.6) | 0 |
| โปรแกรมตู้ | 0 | 0 |

การแก้: ใส่ `overrides` ใน `package.json` ให้ `@firebase/firestore` ใช้ `@grpc/grpc-js@^1.14.7` (รุ่นหลักเดียวกัน และเป็นรุ่นเดียวกับที่ `firebase-admin` ใช้อยู่แล้ว)
ไม่ทำตามคำแนะนำของ npm ที่ให้ถอย `firebase` ไปรุ่น 9.14.0 เพราะเก่ากว่ามากและไม่จำเป็น
ช่องโหว่ทั้งสองข้อเป็นเรื่องฝั่งที่เปิดเป็น "เซิร์ฟเวอร์ gRPC" ซึ่งระบบเราไม่ได้ใช้ ความเสี่ยงจริงจึงต่ำตั้งแต่ก่อนแก้

ตรวจหลังแก้: เทสต์ studio 97 ผ่าน / 0 ล้ม, เทสต์ auth ผ่าน, `next build` ผ่าน, ในเบราว์เซอร์ (ระบบจำลอง) สมัครสมาชิก → เข้าสู่ระบบ → แดชบอร์ด → บันทึกการตั้งค่า ทำงานปกติ

## ทำซ้ำเมื่อมีการอัปเดตไลบรารี
```
npm audit --omit=dev
npm sbom --sbom-format cyclonedx --omit dev > docs/sbom/sbom.cdx.json
```
ควรทำก่อนขึ้นเซิร์ฟเวอร์จริงทุกครั้ง และเมื่อ `npm audit` แจ้งในอนาคต ให้แก้ด้วยการอัปเดตหรือ `overrides` แล้วรันเทสต์และ build ก่อน
