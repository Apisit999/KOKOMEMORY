# แผนปรับเว็บ KOKO Memory: Creative Technology Studio

## 1. เป้าหมายและขอบเขต

รวม 4 สายบริการไว้ในแบรนด์เดียว: ขายซอฟต์แวร์สำหรับธุรกิจ, โปรแกรม Photobooth, งานออกแบบและพิมพ์ 3D, เช่า Photobooth เป้าหมายคือให้ผู้เข้าชมเข้าใจว่าควรเลือกอะไรและดำเนินการต่อได้โดยไม่ต้องอ่านทุกหน้า

สถานะจากโค้ดเดิม: มีระบบจองและบัญชีลูกค้า มีรายการสินค้า/ขอราคา/คำสั่งซื้อ 3D และหลังบ้าน มีแกลเลอรี ภาพและวิดีโอใน public ส่วนซอฟต์แวร์ยังไม่มีระบบสินค้าและไลเซนส์ ความพร้อมใช้งานจริงของระบบเดิมต้องตรวจในสภาพแวดล้อมทดสอบก่อนเผยแพร่

## 2. แนวทางภาพลักษณ์

แนวคิด “Imagine. Create. Remember.” เชื่อมเทคโนโลยีเข้ากับความทรงจำ ใช้พื้นสีถ่าน ตัวอักษรครีม การ์ดเช่าบูธสีชมพู โปรแกรม Photobooth สีเขียวมะนาว งาน 3D สีม่วงอ่อน และซอฟต์แวร์ธุรกิจสีครีม ใช้กริดโล่ง หัวเรื่องขนาดใหญ่ และภาพวางซ้อนแบบภาพพิมพ์ เพื่อให้ต่างจากหน้าแพ็กเกจงานแต่งทั่วไป

ภาพผลงานจริงต้องเป็นตัวเล่าเรื่องหลัก หลีกเลี่ยงตัวเลขยอดขาย รีวิว ราคา โลโก้ลูกค้า และคุณสมบัติสินค้าที่ไม่มีข้อมูลยืนยัน ภาพงาน 3D และหน้าจอโปรแกรมต้องเพิ่มเมื่อมีไฟล์ที่อนุญาตให้เผยแพร่ ภาพทรงกล่องในหน้าแรกเป็นกราฟิกตกแต่ง ไม่ใช่ตัวอย่างสินค้าที่ขาย

## 4. การใช้งานและลูกเล่น

- แสดง CTA ที่ตรงกับความตั้งใจ: เลือกแพ็กเกจ / ดูงาน 3D / ดูโปรแกรม / สอบถามซอฟต์แวร์
- ตัวกรองบริการเป็นปุ่มที่ใช้งานด้วยคีย์บอร์ดและบอกสถานะการเลือก
- ภาพลอยและหมุนอย่างช้า มีปุ่มหยุด และปิดตามการตั้งค่า reduced motion ของอุปกรณ์
- วิดีโอใช้ poster และ preload none ผู้ใช้กดเล่นเอง ไม่มีเสียงอัตโนมัติ มีปุ่มหยุดและข้อความเมื่อเล่นไม่ได้
- การ์ดยกขึ้นเล็กน้อยเมื่อชี้เมาส์ FAQ ใช้ details เพื่อรองรับคีย์บอร์ดโดยตรง
- บนมือถือใช้การ์ดคอลัมน์เดียว ปุ่มกรองขึ้นบรรทัดได้ ข้อความสำคัญอ่านได้โดยไม่ต้อง hover
- รองรับข้อความไทย/อังกฤษจาก locale เดิมในหน้าที่เพิ่มใหม่
- หลีกเลี่ยงแอนิเมชันตาม scroll ที่ทำให้เนื้อหามองไม่เห็นเมื่อ JavaScript ไม่ทำงาน

ระยะถัดไป: เพิ่มตัวช่วยเลือกบริการ 2–3 คำถามและส่งชนิดบริการไปยังฟอร์มติดต่อ โดยไม่ส่งข้อมูลส่วนบุคคลลง URL เพิ่ม modal แสดงผลงานเฉพาะเมื่อมีข้อมูลจริง และพิจารณา 3D viewer แบบโหลดเมื่อกดดูเท่านั้น

## 5. แผนภาพและวิดีโอ

| บริการ | สื่อที่ต้องเตรียม | ใช้ตรงไหน |
| --- | --- | --- |

| โปรแกรม Photobooth | ภาพหน้าจอจริง คลิปขั้นตอนถ่ายจนพิมพ์พร้อมคำบรรยาย | หน้ารายละเอียด / demo |
| 3D Print | ภาพไฟล์เทียบชิ้นงาน ภาพพื้นผิว ภาพการใช้งาน | ผลงาน / สินค้า / วัสดุ |
| ซอฟต์แวร์ธุรกิจ | ภาพหน้าจอที่ลบข้อมูลลูกค้าแล้ว คลิป workflow | หน้าสินค้า / กรณีใช้งาน |

หลักเกณฑ์: ยืนยันสิทธิ์เผยแพร่รูปบุคคลและลูกค้า ลบข้อมูลส่วนตัวจากหน้าจอ ใส่ alt ที่อธิบายภาพตามจริง กำหนดสัดส่วนภาพเพื่อกัน layout กระโดด วิดีโอสั้น 15–30 วินาทีต้องมีภาพปกและคำบรรยายหากมีเสียงพูด ตั้งเป้าภาพแต่ละไฟล์ประมาณ 100–300 KB และวิดีโอสั้นประมาณ 3–8 MB ตามคุณภาพที่ยอมรับได้ วัดขนาดจริงก่อนปรับไฟล์ ใช้ WebP/AVIF ผ่านระบบภาพและ MP4 ที่อุปกรณ์ส่วนใหญ่เล่นได้

ระยะขยายทำ media library หลังบ้าน: ชื่อไฟล์ ชนิดบริการ alt ไทย/อังกฤษ poster ลำดับเผยแพร่ และสถานะอนุมัติ จำกัดชนิดไฟล์และขนาด ตรวจสิทธิ์แอดมิน และใช้ object storage เดิมตามโครงสร้างที่ยืนยันแล้ว

## 6. รายละเอียดที่ต้องตกลงก่อนเปิดขายซอฟต์แวร์

1. ชื่อผลิตภัณฑ์ รุ่น และฟีเจอร์ที่ทำได้จริง พร้อมหลักฐานการสาธิต
2. ระบบปฏิบัติการ รุ่นกล้อง เครื่องพิมพ์ driver และข้อจำกัดอุปกรณ์
3. รูปแบบราคา: ซื้อขาด รายเดือน รายปี หรือสั่งทำ; ภาษี และเอกสารการขาย
4. จำนวนเครื่อง การย้ายเครื่อง การใช้ offline และรอบตรวจสิทธิ์
5. การทดลอง: ระยะเวลา ลายน้ำ ข้อจำกัด และวิธีจบการทดลอง
6. การอัปเดต ระยะเวลาช่วยเหลือ SLA และช่องทางแจ้งปัญหา
7. เงื่อนไขยกเลิก คืนเงิน และสิทธิ์ข้อมูลลูกค้า
8. รุ่น installer วิธีลงนาม checksum และกระบวนการปล่อยเวอร์ชัน

งานเหล่านี้เป็นข้อมูลธุรกิจที่ต้องได้รับคำตอบ จึงยังไม่สมมติราคาและความสามารถลงเว็บ

## 7. ออกแบบระบบขายเพื่อพัฒนาต่อ

แยกข้อมูลจากคำสั่งเช่าบูธและคำสั่ง 3D ที่มีอยู่ สร้าง products, plans, softwareOrders, licenses, releases, activations และ enquiries ตามการตั้งชื่อที่สอดคล้องกับฐานข้อมูลเดิม

ข้อมูลสำคัญ: productId, version, platform, compatibility, price/currency, licenceDuration, deviceLimit, supportedFeatures, supportTerms; order เก็บ snapshot ราคาและเงื่อนไขตอนซื้อ customerId และสถานะการชำระ; release เก็บ storage key, checksum, minimumVersion และสถานะเผยแพร่ ไม่เก็บลิงก์ installer ถาวรที่เปิดให้ทุกคนโหลด

ลำดับ: เลือกสินค้า → เข้าบัญชี → อ่านและยอมรับเงื่อนไข → สร้าง order ฝั่งเซิร์ฟเวอร์ → ชำระเงิน → ยืนยันการรับเงิน → ออกไลเซนส์ → ดาวน์โหลดในบัญชี → เปิดใช้บนเครื่อง ห้ามสร้างไลเซนส์จากสถานะที่เบราว์เซอร์ส่งมาเอง

หากเริ่มด้วยโอนและตรวจสลิปโดยแอดมิน ต้องมีรายการรอตรวจและ audit trail หากใช้ payment gateway ต้องตรวจลายเซ็น webhook และป้องกันประมวลผลซ้ำ ราคาและสิทธิ์อ่านจากเซิร์ฟเวอร์เท่านั้น

ไลเซนส์ใช้ token ที่ตรวจสอบฝั่งเซิร์ฟเวอร์ เก็บค่า hash ของ key แทน raw key ออก download URL อายุสั้นหลังตรวจเจ้าของคำสั่งซื้อ จำกัด activation ตาม plan บันทึกเวลาและเหตุผลของ revoke/reset ใช้ transaction ป้องกันเปิดใช้งานพร้อมกันเกินจำนวนเครื่อง และกำหนด grace period หากต้องรองรับ offline

บัญชีลูกค้าเพิ่ม “ซอฟต์แวร์ของฉัน”: คำสั่งซื้อ ดาวน์โหลดเวอร์ชัน ไลเซนส์ อุปกรณ์ที่เปิดใช้ และประวัติขอความช่วยเหลือ หลังบ้านเพิ่มสินค้า/ราคา/releases/orders/licences พร้อม role ที่แยกสิทธิ์เผยแพร่กับอนุมัติการชำระ

## 9. เกณฑ์ตรวจรับก่อนเผยแพร่

- ตรวจหน้าจอ 360 / 390 / 768 / 1440 px ไม่มีแนวนอนล้น ปุ่มกดง่าย ไม่มีภาพทับ CTA
- ตรวจ navigation ทั้งมือถือและ desktop, ไทย/อังกฤษ, keyboard focus และ reduced motion
- ตรวจเล่น/หยุดวิดีโอ เล่นไม่ได้ และสภาพเครือข่ายช้า วิดีโอไม่โหลดเต็มก่อนผู้ใช้กด
- ตรวจ CTA ไปแพ็กเกจ หน้า 3D และติดต่อ รวมทั้ง flow login/booking/quote เดิม
- ตรวจ metadata รายหน้า ภาพจริง alt และไม่มีราคาหรือรีวิวสมมติ
- วัด performance: ตั้งเป้า LCP ≤ 2.5s, CLS ≤ 0.1 และ INP ≤ 200ms ในสภาพแวดล้อมจริง
- เมื่อต่อ backend เพิ่ม ตรวจสิทธิ์คนอื่น ดาวน์โหลดข้ามบัญชี webhook ซ้ำ licence limit และ audit trail

รอบนี้ยังไม่ได้รัน build หรือทดสอบผ่านเบราว์เซอร์ เกณฑ์ด้านบนเป็นงานตรวจรับที่ต้องทำก่อนเผยแพร่

## 10. สิ่งที่เปลี่ยนในรอบนี้

หน้าแรกและ services ใช้ StudioExperience เพิ่มหน้า software และ software/photobooth ใช้ SoftwareContent เพิ่ม enquiry form ที่เตรียมอีเมลให้ผู้ใช้ส่งเอง พร้อมเลือกประเภทบริการล่วงหน้า เพิ่มลิงก์ Software ในเมนู ใช้ภาพและวิดีโอเดิม รองรับไทย/อังกฤษ ตัวกรองบริการ FAQ และปุ่มควบคุม motion/video เส้นทางเช่าบูธและ 3D เชื่อมเข้าโค้ดเดิม ฟอร์มยังไม่ส่งหรือบันทึก lead บนเซิร์ฟเวอร์ ยังไม่มี payment/license backend และยังไม่ได้ปรับภาพลักษณ์หน้าสาธารณะทั้งหมด

ตรวจรอบนี้: ESLint ผ่านสำหรับไฟล์ที่เพิ่มและแก้ไข และ `npm run build` ผ่านพร้อมสร้างหน้า `/enquiry`, `/software` และ `/software/photobooth` สำเร็จ
